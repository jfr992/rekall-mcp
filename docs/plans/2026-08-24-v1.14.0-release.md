# Rekall v1.14.0 Release Plan

## Problem narrative

PR #96 added first-class Codex lifecycle support, hardened the Claude Code
integration, and documented the audit findings, but `main` still identifies
itself as v1.13.0. Users installing from PyPI or GHCR therefore cannot consume
the merged work through a stable versioned artifact. The release must expose
the change without bypassing the repository's feature-branch, CI, or publish
gates and without changing stored-memory data.

## Release architecture

```text
origin/main @ PR #96
        |
        v
codex/release-v1.14.0
  - release contract tests
  - pyproject.toml + uv.lock = 1.14.0
  - v1.14.0 migration notes
        |
        v
release PR -> required CI -> merged main
        |
        v
tag v1.14.0 -> publish.yml
        |              |
        v              v
 PyPI wheel/sdist   GHCR multi-arch image
        \              /
         v            v
       GitHub release + cold-start smoke checks
```

The release changes distribution metadata and operator documentation only.
It does not add application-layer I/O, alter memory schemas, or write to
Codex-owned native-memory files.

## Typed artifact contract

```python
from dataclasses import dataclass
from typing import Literal

ReleaseVersion = Literal["1.14.0"]
ReleaseTag = Literal["v1.14.0"]

@dataclass(frozen=True)
class ReleaseArtifacts:
    project_version: ReleaseVersion
    lockfile_version: ReleaseVersion
    migration_target: ReleaseVersion
    tag: ReleaseTag
    data_migration_required: Literal[False]
```

Published artifacts are valid only when the project metadata, root lockfile
package, migration target, and Git tag describe the same semantic version.

## Concrete expected output

- `pyproject.toml`: `version = "1.14.0"`.
- Root `rekall-mcp` entry in `uv.lock`: `version = "1.14.0"`.
- `docs/MIGRATION.md` starts with a v1.13.0 → v1.14.0 section covering Codex,
  Claude Code hardening, targeted recall, installation, rollback, and the fact
  that no data migration is required.
- A feature-branch PR passes required CI and is merged without a direct push to
  `main`.
- Tag `v1.14.0` triggers `publish.yml`; PyPI and GHCR publish successfully.
- The GitHub release title is `v1.14.0 — memory for Codex, hardened for Claude`.
- Cold-start checks resolve `rekall-mcp==1.14.0`, start the versioned container,
  and report `"server": "rekall"` from `/health`.

## Rollback

Do not move or overwrite an existing tag. If publishing fails, leave the tag
for diagnosis, fix forward on a new feature branch, and publish a patch release.
The v1.14.0 upgrade itself is reversible because it requires no memory-schema
or data migration.
