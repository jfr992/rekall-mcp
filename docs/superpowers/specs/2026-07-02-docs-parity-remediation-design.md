# Docs/Scripts Parity Remediation — Design

**Date:** 2026-07-02
**Status:** Approved (pending final spec review)
**Input:** 4-agent parity audit (API surface, install path, Claude bundle, deep docs) + adversarial design review, both 2026-07-02.

## Problem

Core product surface (README API tables, MCP tools, install.sh, hooks) has near-perfect doc parity. The operational periphery rotted through the v1.5 nested-layout migration and v1.7 rename: six docs show the flat YAML layout, three docs show the pre-v1.5 recall formula, README claims the wrong license, the Makefile and start/stop scripts contain commands that fail outright, `.env.example` documents variables the code never reads, and `src/` carries a dead Spectro subsystem that ImportErrors at startup if enabled.

## Decision record (adversarial review adjudication)

All 8 red-team attacks accepted, four with modifications:

1. **Spectro scope** — accepted, widened. Deletion spans **5** files (`src/config.py`, `src/tools/config.py`, `src/tools/registry.py`, `src/tools/loader.py`, `src/server.py`), not one. `src/tools/builtin/spectro.py` does not exist, so `loader.py:88-91` is a live ImportError bomb when `TOOLS_ENABLED=spectro`.
2. **PR boundary** — accepted, restructured. Old split ("no behavior change" vs "behavior change") leaked. New rule: **PR1 = text only** (markdown + `.env.example` + SKILL.md). **PR2 = anything executable** (Makefile, scripts, compose, code, tests).
3. **Type enum** — accepted, modified. `server.py:258-259` accepts 8 types including both `session` and `summary`; `compact.py:95` generates `summary`. CLI aligns to the full 8-type server set. CLAUDE.md schema gains `session` and keeps `summary` (no rename ever happened).
4. **Healthcheck coverage** — accepted. Fix all three race pairs: `qdrant`→`mcp`, `qdrant`→`mcp-dev`, `qdrant-test`→`test`. Healthcheck method must be verified empirically — Qdrant images may lack curl/wget (plausibly why the block was commented out). Fallback: TCP-based check.
5. **REKALL_HOST** — accepted, reworded. Not a phantom: `start-rekall.sh:30` shims `REKALL_HOST`→`HOST`. MIGRATION.md gets corrected wording (script-level input var; direct server env is `HOST`), not deletion.
6. **Parity test mechanism** — accepted, specified below.
7. **`make run`** — accepted: `PYTHONPATH=src uv run python -m server` (uv venv, no cd).
8. **Flat-layout count** — accepted: spec enumerates exact locations instead of counts.

Additional ponytail call: `make memory-clean` is **deleted**, not rewired. It is broken today (calls a nonexistent CLI subcommand), so no working user exists; the REST endpoint `POST /api/memory/cleanup` needs a JSON body and cannot honor the target's "interactive" promise. Help text gets one line pointing at the endpoint.

## PR2 — Executable hygiene (TDD, lands after PR1)

1. **Spectro excision** — remove all spectro references from the 5 files above plus any `config.yaml.example` keys. Acceptance: `grep -ri spectro src/ config.yaml.example` returns nothing; full pytest green. No tests reference spectro (verified).
2. **CLI type enum** — `cli.py:37-38` choices → the 8-type server set (`decision|learning|preference|requirement|fact|note|session|summary`). Failing test first; ideally derive the choice list from a shared constant with `server.py:258` rather than duplicating.
3. **Compose healthchecks** — healthcheck on `qdrant` and `qdrant-test`; `depends_on: condition: service_healthy` on `mcp`, `mcp-dev`, `test`. Verify empirically (`docker compose up`, confirm `healthy`); if the image lacks curl/wget, use a TCP-based check.
4. **Makefile** — `memory-stats` flat glob → recursive; `run` → `PYTHONPATH=src uv run python -m server`; delete `memory-clean` target, help text points at `POST /api/memory/cleanup`.
5. **scripts/** — `docker-compose` → `docker compose` in start/stop; `PYTHONPATH=src` on the server launch in `start-rekall.sh`.
6. **tests/test_docs_parity.py** — three assertions:
   - (a) Routes: import the server app, walk starlette route objects (path + methods), normalize `{param}` placeholders; parse README REST table rows; assert every registered route appears (README ⊇ routes for `/api/*` paths, method-aware).
   - (b) Tools: collect registered `@mcp.tool` names; assert each appears in the README tools table.
   - (c) Env vars: parse `.env.example` keys; assert each is referenced in `src/` or `docker-compose.yaml`.

**Ordering:** PR2's parity test asserts README content that PR1 creates (synthesize/status rows) — PR1 merges first.

## Testing

- PR1: `uv run --extra dev pytest -v` stays green (text-only should be a no-op); manual re-read of each edited section against the cited code lines.
- PR2: failing test first per change; full suite + `docker compose --profile test run --rm test`; compose healthcheck verified against live `docker compose ps`; `make memory-stats` exercised against the real store (expect non-zero count).

## Risks

- Healthcheck may not work with the shipped Qdrant image → empirical verification step is mandatory, TCP fallback specified.
- Parity test could be brittle to README table reformatting → parser matches table rows by backticked path prefix, not column position.
- Existing installs registered the MCP server under other names (e.g. `memory`) → docs standardize on `rekall`; MIGRATION.md already covers renames, no code impact.
